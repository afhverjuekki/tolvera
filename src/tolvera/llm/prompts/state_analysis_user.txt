Analyze this behavior to determine what states (if any) are needed:

"{description}"

IMPORTANT: Many behaviors DO NOT need any custom states!

Check if this is a simple physics behavior that can be achieved with just forces:
- Gravity/falling → No states needed, just apply downward force
- Wind/drift → No states needed, just apply directional force  
- Basic attraction → No states needed, just calculate force toward target
- Random movement → No states needed, just apply random forces

Only create states if the behavior requires:
- Memory (remembering positions, history, etc.)
- Changing parameters over time
- Complex interactions that need stored information
- Resource tracking (energy, health, etc.)

REMEMBER CORE PROPERTIES ALREADY EXIST:
DO NOT create states for these particle properties (access via tv.p.field[i]):
- position/pos (use tv.p.field[i].pos)
- velocity/vel (use tv.p.field[i].vel) 
- mass, size, speed, active, species

If the behavior just needs:
- Basic movement → Use forces, no position/velocity states needed
- Faster/slower movement → Use existing mass/speed in force calculations
- Different sizes → Already handled by core size property

Only create states for NEW information like:
- home_pos, target_pos (specific positions to remember)
- energy, health, hunger (resource management)
- memory, state_history (behavioral memory)
- interaction_strength (relationship tracking)

IMPORTANT STATE CONSIDERATIONS:
- If behavior mentions "remember position" or "return home", include a position state (e.g., home_pos as ti.math.vec2)
- If behavior mentions "target" or "goal", include appropriate position/target states
- If behavior mentions "memory" or "history", include states to track past information
- For time-based behaviors, include temporal states

CRITICAL POSITION STATE PATTERNS:
- "return home" → MUST include home_pos (ti.math.vec2) in particle_states
- "remember where" → MUST include appropriate position state (ti.math.vec2)
- "go back to" → MUST include saved position state (ti.math.vec2)
- "return when tired" → MUST include both tiredness (ti.f32) AND home_pos (ti.math.vec2)
- "remember their home" → MUST include home_pos (ti.math.vec2)

Example for "return home" behaviors:

CRITICAL RANGE GUIDELINES:
- For multiplicative states (energy, activity, strength): Use 0-100 range, not 0-1
- For position states: Use actual screen coordinates (e.g., 0-800 for X, 0-600 for Y)
- For counter states: Use appropriate integer ranges (e.g., 0-1000)
- For angle states: Use 0-360 or 0-6.28 (2π) for radians
- Avoid 0-1 ranges unless specifically for normalized values
