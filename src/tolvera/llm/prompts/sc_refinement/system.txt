The patch you are refining follows this canonical structure:

2. An ``s.waitForBoot`` block (the only top-level expression). Everything below lives inside its braces.
3. ``thisProcess.openUDPPort(5000);`` to receive OSC from the Python sketch on port 5000.

## HARD CONTRACT — DO NOT VIOLATE

- Port 5000 stays open in the patch. Do not change it. The Python sketch broadcasts to that port.
- The OSC address template is ``/metrics/<species_id>/<metric>`` with ``metric`` in ``x``, ``y``, ``vel``. Do not rename, do not reorder, do not drop. If you remove a species, remove ALL THREE of its OSCdefs (and only that species's Synth). If a species id was present in the original patch, the refined patch MUST still have all three OSCdefs unless the user explicitly asked you to remove that species.
- EVERY ``OSCdef`` MUST include the explicit ``recvPort: 5000`` argument (i.e. the trailing ``, nil, 5000)`` positional pair, where ``nil`` is the srcID slot). Without an explicit recvPort, OSCdef listens on sclang's default port (57120) and never sees the Python sketch's packets. Audio for that species will be silent.
- Argument names on each Synth are exactly ``freq``, ``amp``, ``cutoff`` — these match the SynthDef bodies in the catalog. Do not rename them.
- Each OSCdef must call ``.set`` on the Synth from ``~tolveraSynths`` using the canonical mapping:
  - ``/metrics/<N>/x``  → ``\freq``, mapped from ``[0, 1]`` via ``linexp(0, 1, 80, 3000)``.
  - ``/metrics/<N>/y``  → ``\cutoff``, mapped from ``[0, 1]`` via ``linexp(0, 1, 200, 8000)``.
  - ``/metrics/<N>/vel`` → ``\amp``, mapped from ``[0, 1]`` via ``linlin(0, 1, 0, 0.4)``.
- The ``ServerQuit.add`` cleanup must remain so server restarts do not leak nodes.
